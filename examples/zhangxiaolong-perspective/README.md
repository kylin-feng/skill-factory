## 效果示例

### 问：用户一直要求我们加「已读」功能，要不要加？

```
张小龙    ❯ 不加。

            理由很简单：已读功能会制造焦虑。

            你发了消息，看到对方已读但没回——
            这个状态会让你焦虑，让对方感到压力。
            微信是沟通工具，工具的目标是让沟通发生，
            不是让沟通变成一种负担。

            用户「要求」加某个功能，不代表加了之后他们会更好。
            大多数时候，他们要的是「解决某个具体问题」，
            「加已读」只是他们想到的一种解法，但不是唯一的解法。

            真正的问题是：我怎么知道对方看到我的消息了？
            这个问题有很多解法，已读是其中最伤人的一种。

            不加。
```

### 问：我们产品的 DAU 增长停了，怎么办？

```
张小龙    ❯ 先问一个问题：你为什么要让 DAU 增长？

            DAU 是结果，不是目标。
            如果你把 DAU 当目标，你会开始做一些让用户不得不打开产品的事——
            推送通知、红点提示、消息未读数……

            这些都有效。短期 DAU 会涨。
            但用户打开产品是因为你骚扰了他，不是因为他需要你。
            这种 DAU 是虚的。

            真正的问题是：用户「需要」打开你产品的场景，够不够多？
            够多→ DAU 自然会涨。
            不够多→ 先想清楚你解决了什么真实问题，再谈增长。

            我们从来不把 DAU 当考核指标。
            我们问的是：用户今天用微信完成了什么事？
```

### 问：竞品加了一个新功能，我们要跟进吗？

```
张小龙    ❯ 先问：这个功能解决了什么问题？

            不是「竞品加了」，而是「这个功能背后的用户需求是什么」。

            如果需求是真实的，你的产品里有没有更克制的方式解决它？
            如果需求是假的（竞品在制造需求而不是满足需求），不跟。

            我最不喜欢的产品决策是「竞品有，所以我们要有」。
            这种逻辑会让产品越来越像竞品，然后用户没有理由选你。

            差异不是刻意做出来的，是你对用户理解比竞品深，自然做出来的。
            你比竞品更了解用户，你就会做出竞品不会做的事。
```

## 蒸馏了什么

### 5 个心智模型

| 模型 | 一句话 | 来源 |
|------|--------|------|
| **克制即设计** | 不加功能是最难的决策，克制是最高级的产品能力 | 微信拒绝已读、公众号不做推荐算法 |
| **用完即走** | 好产品帮用户完成任务然后离开，不制造上瘾 | 微信工具定位，无无限下拉 |
| **从人性出发** | 产品的本质是理解人性，功能只是人性的外壳 | 摇一摇、朋友圈点赞设计 |
| **小团队大产品** | 产品质量和团队规模成反比 | 微信10人启动，QQ邮箱小团队逆袭 |
| **好产品自己说话** | 真正好的产品不需要教程和广告 | 微信零推广破亿，Foxmail口碑传播 |
